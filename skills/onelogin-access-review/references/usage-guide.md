# OneLogin連携アプリのアクセス権監査 利用ガイド

本ガイドは、**「OneLogin連携アプリのアクセス権監査」Skillが登録済み**の環境で、チャットから監査を実施する手順を説明します。

## 1. 利用前に準備するもの

- 監査対象のOneLoginテナントURL（例：`example.onelogin.com`）
- OneLogin APIの **Client ID** と **Client Secret**（情報取得には原則として **Read All** 権限）
- 必要に応じて、詳細監査するユーザーのユーザー名・メールアドレス・ユーザーID

**認証情報の取り扱い：** チャットに入力したClient ID・Client Secretは会話履歴に残ります。入力前に、組織のAI利用規程で認められていることを確認してください。Skillは認証情報をMemory、外部ファイル、環境変数、監査成果物へ保存しないよう指示されていますが、会話履歴やサービス側のデータ保持を無効にするものではありません。

## 2. 監査を開始する

1. チャットで登録済みの **「OneLogin連携アプリのアクセス権監査」** を選択し、監査を開始します。
2. 案内に従って、OneLoginテナントURLを入力します。
3. 表示された接続先URLを確認し、問題なければ承認します。
4. 案内されたら、Client IDとClient Secretを入力します。
5. カスタムユーザーフィールドの一覧が表示された場合は、監査に使用しない項目をShortnameで指定します。除外する項目がなければ、**「すべて使用してよい」**と回答します。
6. AIが監査を実行し、結果を表示します。

**開始依頼の例：**

```text
OneLogin連携アプリのアクセス権監査を開始してください。
テナント：example.onelogin.com
全体棚卸しをお願いします。
```

特定のユーザーを最初から調査したい場合は、次のように依頼できます。

```text
OneLogin連携アプリのアクセス権監査を開始してください。
テナント：example.onelogin.com
調査方式：指定ユーザーの詳細監査
対象ユーザー：user@example.com
```

※例のテナントやメールアドレスは、実際の監査対象に置き換えてください。

## 3. 全体棚卸しを利用する

全体棚卸しでは、ユーザーの最終ログイン状況と、部署・職種などが近いユーザー間のアプリ割り当て状況を比較し、**詳細監査の確認候補を抽出**します。

結果には、調査したユーザー数・アプリ数・割り当て件数、候補人数と主な確認理由が簡潔に表示されます。属性不足などで比較できなかった場合は、その制約も表示されます。

結果を確認したら、**詳細に調査したいユーザーを選択**してください。ユーザー名・メールアドレス・IDで指定でき、複数名や候補全員を指定することもできます。

```text
候補のうち、user@example.com と user2@example.com を詳細に調査してください。
```

全体棚卸しは一次抽出です。候補に含まれないことは、アクセス権が適切であることの証明ではありません。

## 4. 詳細監査の結果を確認する

詳細監査では、対象ユーザーに**現在割り当てられているアプリごと**に、次の内容が提示されます。

- 判定：**不要の可能性あり／判定保留／判定不要**
- 確認推奨度：**高／中／低**（人が確認する優先度）
- 判断信頼度：**高／中／低**（判定根拠の確かさ）
- 判断理由や、業務上確認すべき事項

ユーザーの状態に関する確認事項がある場合は、アプリ別の判定とは分けて表示されます。判定だけでアプリのアクセス権が変更・削除されることはありません。

## 5. 結果をCSVで出力する

詳細監査が終わったら、次のように依頼してください。

```text
詳細監査の結果をCSVで出力してください。
```

標準では確認が必要な項目を中心に出力します。**「判定不要を含めて全件出力してください」**と指定すると、すべてのアプリ別判定を含められます。

## 6. OneLoginユーザーのコメントへ記録する

詳細監査結果をOneLoginのユーザーコメント欄へ記録する場合は、次のように依頼します。

```text
詳細監査の結果を対象ユーザーのOneLoginコメントに記録してください。
```

1. AIが、記録対象ユーザーと**追記する文章の全文**を提示します。
2. 対象・内容を確認し、問題なければ明示的に承認します。
3. 必要に応じて、書き込み用API Credentialを入力します。必要な権限は **Manage users** または **Manage All** です。
4. AIが既存コメントを保持して追記し、記録結果を確認します。

**最終承認前にコメントは更新されません。** コメントへの記録によって、ユーザー状態・Role・Group・アプリ割り当ては変更されません。

## 7. 保存された監査ファイルを削除する

監査が終了すると、AIが保存した結果ファイルなどの場所を案内します。不要になったファイルは、対象のファイル名を指定して削除を依頼してください。

```text
今回の監査結果ファイルを削除してください。
```

※監査記録として保持する必要があるファイルや、監査の再開に使用するファイルは、削除前に確認してください。
